# 接口文档 —— 图斑地图数据（esp 模块）

> 版本：2026-09-10　|　模块：`modules/esp`（Swagger 分组 106-esp）
> 数据源：`ESP_MAP_AREA` / `ESP_MAP_PROJECT`（导入自前端 `packages/display/data/{area,project}_merged_all.geojson`，见《数据库设计说明-图斑数据入库》）

## 通用约定

- 响应结构：`{code, msg, data}`，成功 `code=200`，业务/参数错误 `400`，系统异常 `500`；
- 权限：登录即可访问（`@RequiresPermissions("user")`），供综合展示/一张图等页面共用，无需挂菜单权限；
- 公共查询参数 `batch`（可选，string）：批次**精确**匹配，取值 `第一批` / `第二批` / `新增`；
  不传或传空串 = 查全量；传不存在的值返回空列表 `data: []`（2026-09-11 新增）；
  其中 `新增` 的下发需求见第 3 节（待后端支持）；
- 其余场景一次性全量返回（无分页）：片区约 182 行（≈417KB），项目约 529 行（≈1.56MB）；
- `data` 数组元素的字段键与前端 `modules/packages/ifco/views/ifco/overview/polygon-types.ts` 的
  `AreaPolygonProps` / `ProjectPolygonProps` **完全一致**（GeoJSON 属性原名大写键），
  另含小写 `geometry`：自包含 TopoJSON **原文**（字符串，未做任何二次包装）。

## 1. 片区范围查询

```
GET /a/esp/map/areas?batch=第一批    # batch 可选：第一批/第二批，不传=全量
```

**响应**（data 元素，26 键；原 FUNC_TYPE 已于 2026-09-11 拆分为 FUNC_TYPE_NAME / FUNC_TYPE_VALUE 两键。
批次行数参考：第一批 80 行、第二批 102 行）：

| 字段 | 含义 | 备注 |
|---|---|---|
| BATCH | 批次：第一批/第二批 | |
| A_UID | 合并后片区唯一号（PQ001…） | 唯一 |
| OLD_A_UID / OLD_A_NO | 原片区唯一号 / 原片区编号 | 回溯用 |
| A_SEQ | 片区顺序号 | 数值 |
| DIST / AREA_NAME | 行政区 / 片区名称 | |
| FUNC_TYPE_NAME | 功能定位-中文名 | 标准字典：交通导向/文旅导向/公服导向/生态导向/产业导向/康养导向，多个逗号分隔 |
| FUNC_TYPE_VALUE | 功能定位-编码 | TOD/COD/SOD/EOD/IOD/HOD，多个逗号分隔；POD=公园导向（字典外补充） |
| WG_BIG / WG_SUB | 五改大类 / 五改分类·四好目标 | |
| INV_BIL | 投资估算（亿元） | 原文，个别为非数值文本 |
| FUND_SRC | 资金来源及落实情况 | |
| RESP_BODY / PROJECT_CHANGE | 片区责任主体 / 片区项目调整说明 | |
| START_RAW / END_RAW / START_DATE / END_DATE / DATE_STAT | 开完工原始值 / 标准化日期文本 / 核对状态 | 日期文本列可能含"策划中"等 |
| AREA_HA | 图斑面积（公顷） | 数值 |
| PROJECT_INV_BIL / PROJECT_CNT | 片区项目投资合计（亿元）/ 项目数 | 数值 |
| DATA_SRC / UID_NOTE | 数据来源 / 唯一号说明 | |
| geometry | **自包含 TopoJSON 原文** | 见下方前端还原方法 |

## 2. 项目图斑查询

```
GET /a/esp/map/projects?batch=第二批  # batch 可选：第一批/第二批，不传=全量
```

**响应**（data 元素，39 键 = 38 个属性字段 + geometry）：含 areas 接口的全部共有属性字段（不含 A_SEQ/RESP_BODY/PROJECT_INV_BIL/PROJECT_CNT/PROJECT_CHANGE），
支持同样的 `batch` 参数。批次行数参考：第一批 121 行、第二批 408 行。另增加以下字段：

| 字段 | 含义 | 备注 |
|---|---|---|
| P_UID | 合并后项目图斑唯一号（PQ001_1 格式） | 唯一 |
| OLD_P_UID / P_SEQ | 原图斑唯一号 / 片区内顺序号 | |
| A_UID | 所属片区唯一号 | 关联 areas 接口的 A_UID |
| GIS_NAME / GIS_DESC | 图斑原名称 / 图斑描述 | |
| FUNC_TYPE_NAME / FUNC_TYPE_VALUE | 功能定位-中文名 / 编码 | 同 areas 接口 |
| PJ_ID / PJ_NAME / BODY / RESP | Excel 项目 ID / 项目名称 / 实施主体 / 责任主体 | |
| A_INV_BIL | 所属片区投资估算（亿元） | 数值 |
| PJ_CHANGE | 项目增减情况 | |
| CONTENT / PRE_PROC / BLD_NATURE / PROG | 建设内容 / 前期手续 / 建设性质 / 项目进展 | 第二批数据 |
| INV_2026 / INV_2027 | 2026 / 2027 年计划投资（亿元） | 数值 |
| MAT_METHOD | 与清单匹配方式说明 | |
| **geometry** | **自包含 TopoJSON 原文（与 areas 接口一致）** | 还原方法见下方前端消费示例 |

响应行完整键序（39 键）：

```
BATCH, A_UID, OLD_A_UID, OLD_A_NO, DIST, AREA_NAME, FUNC_TYPE_NAME, FUNC_TYPE_VALUE,
WG_BIG, WG_SUB, INV_BIL, FUND_SRC, START_RAW, END_RAW, START_DATE, END_DATE, DATE_STAT,
AREA_HA, DATA_SRC, UID_NOTE, P_UID, OLD_P_UID, P_SEQ, GIS_NAME, GIS_DESC, PJ_ID, PJ_NAME,
BODY, A_INV_BIL, RESP, PJ_CHANGE, CONTENT, PRE_PROC, BLD_NATURE, PROG,
INV_2026, INV_2027, MAT_METHOD, geometry
```

## 3. 批次「新增」下发需求（2026-09-17 提出待后端支持）

前端数据看板批次下拉已增加「新增」档并按 `batch=新增` 传参，等后端支持后无需前端改动直接生效：

- **口径**：`batch=新增` 应下发 `ESP_MAP_AREA.is_approve='2'` 的**方案填报新增（待审查）片区**；
- **现状**：`EspMapDao.findAreas` / `findProjects`（EXISTS 子查询）硬编码 `is_approve='1'`，
  新增片区被过滤，当前该档行数为 **0**（前端传 `batch=新增` 按精确匹配规则返回空列表 `data: []`）；
- **待办**：两个查询各增加分支（如 `batch='新增'` 时改查 `is_approve='2'`，注意此时项目图斑
  的 EXISTS 口径同步放开）；新增片区行字段与现有行一致，geometry 为 WKT；
- 前端相关：下拉计数、地图着色（按 BATCH 兜底灰）、各图表空数据兜底均已就绪。

## 前端消费示例（TopoJSON 还原）

```ts
import * as topojson from 'topojson-client';

const { data: areas } = await fetch('/js/a/esp/map/areas', { __ajax: 'json' }).then(r => r.json());
// areas[i] 直接满足 AreaPolygonProps（TS 断言即可），geometry 单独还原：
const t = JSON.parse(areas[0].geometry);
const feature = topojson.feature(t, t.objects.feature); // GeoJSON Feature（MultiPolygon）
// 可直接用于 Leaflet/Mapbox GL 的 GeoJSON source
```

数值字段（A_SEQ、P_SEQ、AREA_HA、PROJECT_CNT、A_INV_BIL、PROJECT_INV_BIL、INV_2026、INV_2027）为 JSON 数值类型；其余为字符串或 null（库中空值即 null，前端注意判空）。

## 实现与联调记录（2026-09-10）

- 代码：`polygon/dao/EspMapDao`（SQL 引号别名锁定大写键，达梦/PG 双库一致）→
  `polygon/service/EspMapService`（按 polygon-types 字段序组装 LinkedHashMap，CLOB 防御性转 String）→
  `api/web/map/EspMapController`；
- 实测（本机起 web-api 连局方库）：两接口 200；行数 182/529，键序全部一致；
  全部行 geometry 可解析为合法 Topology（objects.feature=MultiPolygon）；
  官方 `topojson-client` 从接口响应解码成功（MultiPolygon）；
- 数据库行与接口响应均为导入工具写入的原文，未做转换。
