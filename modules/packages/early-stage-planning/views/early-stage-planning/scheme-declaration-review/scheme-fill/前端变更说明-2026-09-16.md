## 9. 字典接口需求（2026-09-17 追加，待后端实现）

方案填报页三组下拉目前前端硬编码，希望改为接口下发（列表页搜索区 + 填报表单
共用；现无对应接口——`/esp/dict/*` 是三师库字典且挂 `esp:expert:view` 权限，
填报用户无权调用）：

```
GET /a/esp/schemeFill/dict        （建议权限 user，与方案填报其他接口一致）
```

响应 `data`：

```json
{
  "districts": ["汉阳区", "江岸区", "…"],
  "funcTypes": ["TOD", "EOD", "IOD", "SOD", "COD", "HOD", "POD"],
  "batches": ["第一批", "第二批"]
}
```

| 键 | 用途（前端消费处） | 数据来源建议 |
|----|--------------------|--------------|
| `districts` | 列表搜索-行政区、表单-片区基本信息-行政区 | `js_sys_area` 武汉市下辖区或按业务收窄（**需产品确认范围**，见下） |
| `funcTypes` | 列表搜索-功能定位、表单-片区功能策划-功能定位 | 直接暴露 `SchemeFillService.FUNC_DICT` 的编码集（`TOD/COD/SOD/EOD/IOD/HOD/POD`） |
| `batches` | 列表搜索-片区批次、表单-片区基本信息-片区批次 | 固定枚举或 `SELECT DISTINCT batch`（排除 null） |

⚠️ 行政区范围决策点：现前端硬编码为 7 个中心城区；若取 `js_sys_area` 全量下辖区
为 13 个左右（含东西湖/汉南/蔡甸/江夏/黄陂/新洲等）。另外存量片区数据的区划还有
「经开区/东湖风景区」等**功能区**写法（不在行政区表），若字典不含它们，存量值将
无法通过下拉筛出——范围请与业务确认后定，前端只认接口返回值。

改造类别（projects[].category 五类）与项目/片区资金来源枚举暂维持前端硬编码，
如需一并字典化，可在本接口加 `categories` / `projectFundSources` / `areaFundSources` 键。

## 10. 存量项目行放开编辑/删除（2026-09-18 追加，待后端实现）

业务口径变更：已批准片区编辑页中，**存量导入项目（fillFlag=0）不再只读**——
与填报行一样可编辑、可删除。前端已放开交互并把存量行**带回保存提交**：

- 提交的 `projects[]` 现在包含全部行；存量行带回回显的 `pUid` + `fillFlag:"0"`
  （DTO 已有这两个字段），被删除的存量行自然不在数组中；
- 现行后端 `replaceProjects` 对 fillFlag=0 行**跳过不重建**——即后端未配套前，
  存量行的编辑/删除**不会落库**（也不会产生重复行，属安全过渡态）。

后端 TODO（`replaceProjects` 配套）：

1. **更新**：提交项带 `fillFlag=0` + `pUid` → 按 pUid **原位 UPDATE** 该存量行
   （pj_name/wg_big/body/inv_bil/fund_src/year_invest/start_date/end_date/content/
   plan_files/geometry；保持 fill_flag=0 与存量专属列不动，p_seq 不变）；
2. **删除**：库里该 a_uid 下 fill_flag=0 的行，其 pUid **未出现在提交数组**中 → 删除
   （建议物理删，与填报行口径一致）；
3. 填报行逻辑不变（无 pUid 或 fillFlag=1：全删全插 fill_flag=1）。
