## 问题 1：退回修改后主审单位仍可再次审查（状态机漏洞）【建议优先修复】

**现象**：主审提交「退回修改」后（片区状态 `returned`），主审仍可以：

- 在审查页**再次提交审查结论**（通过 / 退回修改）；
- **再次发起联合审查**。

**期望业务口径**：退回后流程回到填报单位——主审不能再审、不能再发起联审；待填报单位
修改后重新提交（`save` 传 `submitType=submit`，状态回 `reviewing`）后，主审才恢复可审。

**原因**：`SchemeReviewService` 中 `mainSubmit` / `jointPush` 的状态校验只拦截了
`passed`（终态）与 `unsubmitted`（未提交），未拦截 `returned`；`form` 接口返回的
`actions.canMainReview` / `actions.canJointPush` 同样未排除 `returned`。

**建议修改**（`modules/esp/src/main/java/com/jeesite/modules/esp/scheme/service/SchemeReviewService.java`）：

1. `mainSubmit(...)`——在 `unsubmitted` 校验之后增加：

   ```java
   if (EspMapArea.STATUS_RETURNED.equals(status)) {
       throw new IllegalArgumentException("该片区已退回填报单位修改，待其重新提交后方可再次审查");
   }
   ```

2. `jointPush(...)`——同口径增加相同拦截（退回后主审同样不能再发起联审）；

3. `actions(...)`——`canMainReview` / `canJointPush` 的条件增加
   `&& !EspMapArea.STATUS_RETURNED.equals(status)`。

**前端已做兼容**（后端修复前联调不受阻）：

- 审查列表「审查」入口已排除「退回修改」状态（主审此时只有「查看」）；
- 审查页对主审在退回态隐藏填写区，说明条提示「该片区已退回填报单位修改，待其重新提交
  后方可再次审查」（前端按行/详情 `reviewStatus` 判断，与后端修复后口径一致，后端
  修复后前端无需回改）。

## 问题 2：联合审查弹窗无可选单位（联审单位字典未维护）

**现象**：审查页点「联合审查」，弹窗候选单位列表为空。

**查证结论**（2026-09-20）：

- 弹窗数据源 `GET /a/esp/schemeReview/dict` 的 `jointUnits` ＝ 授有机构角色
  `esp_pqchsbsc_joint_review` 的部门（查框架表 `js_sys_office_role`，与 ifco 报送单位
  同一先例）；
- 当前环境尚未在【系统设置 → 机构管理】给市级部门关联该角色，因此字典返回空；
- 框架**没有**「按角色查机构」的公开接口（`/sys/office/listData` 只能查全量机构、
  不支持按角色过滤），前端无法绕过字典直接取全量机构——且 `jointPush` 也会校验所选
  单位必须在联审字典内，放开会造成前后端口径不一致。

**处理建议**（二选一）：

- **方案 A（推荐，无需改代码）**：管理员在【系统设置 → 机构管理】为参与联审的市级部门
  关联角色 `esp_pqchsbsc_joint_review`，字典即返回这些单位；
- **方案 B（仅当业务要求候选＝全部市级部门）**：需后端同步调整 `jointPush` 的单位合法性
  校验与 `currentUserScope` 的联审身份判定口径——注意这会放宽联审数据权限
  （所有部门都成为联审方），需业务方确认后再做。

**前端已做**：弹窗空态已区分「加载中 / 无可选单位」，后者直接提示上述维护入口。
