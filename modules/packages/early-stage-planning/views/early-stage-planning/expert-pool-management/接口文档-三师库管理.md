# 前期谋划（三师库管理） —— 接口文档（v1）

> 后端模块：`modules/esp`（jeesite-module-esp）
> 前端对接：`@jeesite/early-stage-planning` 的 `expert-pool-management`（当前为 mock，接口就绪后替换 expert-store.ts 内实现）
> 文档版本：2026-09-21
> - v1：三师信息管理 / 随机分配三师 / 考评分析 三个子页面的全部后端接口
> - v1.1：抽取片区改查 ESP_MAP_AREA（area_name=key / a_uid=value）；新增按片区回显最近抽取记录；同一片区再次确认选用覆盖原专家

## 页面与接口对应

| 前端页面 | 菜单 | 接口前缀 | 权限 |

## 通用约定

- **鉴权**：JeeSite 登录态（Shiro `${adminPath}/** = user`），前端 defHttp 携带；每个接口另校验 `@RequiresPermissions` 权限串（菜单 SQL 已注册，需给角色授权）。
- **响应结构**：所有接口统一返回 `{code, msg, data}`；成功 `code=200`，业务/参数错误 `code=400`（`msg` 为中文提示），系统异常 `code=500`。
- **分页结构**：`data = {total, pageNum, pageSize, list}`；入参 `pageNum`（默认 1）、`pageSize`（默认 10，上限 100）。
- **日期格式**：业务日期一律 `yyyy-MM-dd` 字符串（joinDate / time / drawDate）。
- **布尔转换**：库内 `selected/assign_flag` 为 char(1)，接口层统一转布尔（`selected/assignFlag`）。
- **专家行结构**（列表/表单/抽取卡片/考评列表共用）：

```json
{ "id": "xx", "name": "张伟", "gender": "男", "age": 35,
  "phone": "13800000000", "idCard": "420102xxxxxxxx1234",
  "field": "城乡规划学", "title": "高级工程师",
  "org": "武汉市规划设计研究院", "orgType": "事业单位",
  "joinDate": "2026-09-01", "selected": false,
  "career": "……", "reviewExperience": "……" }
```

- **三师角色**：`planner`=责任规划师 / `architect`=责任建筑师 / `assessor`=责任评估师。
- **打分口径**：三维度（活跃度/专业覆盖度/评审效率）提交星数 0~5（0.5 步进），一颗星 2 分、半颗星 1 分；落库存 0~10 整数得分，接口返回同时给出 `xxxStars`（=得分÷2）与 `xxxScore`。
- **批量导入**（信息管理工具栏按钮）：下载模版 `GET /a/esp/expert/importTemplate`（MinIO 直链）或 `GET /a/esp/expert/importTemplateFile`（后端转发文件流）；导入 `POST /a/esp/expert/importData`（multipart，字段名 `file`）。模版对象键配置 `esp.expert.importTemplateObjectKey`。

## 1. 字典接口（GET，权限 `esp:expert:view`）

### 1.1 下拉选项集合 `GET /a/esp/dict/options`

表单/搜索/抽取筛选共用的选项（值即中文标签，来自种子表 ESP_DICT）：

```json
{ "code": 200, "data": {
  "fields": ["城乡规划学", "建筑学", "…共17项"],
  "titles": ["高级工程师", "正高级工程师"],
  "orgTypes": ["民营企业", "国有企业", "党政机关", "事业单位", "其他"],
  "genders": ["男", "女"] } }
```

### 1.2 抽取片区下拉 `GET /a/esp/dict/areas`

片区范围表 `ESP_MAP_AREA`（未删除且有名称/唯一号）；`area_name` 为 key（展示），`a_uid` 为 value（取值）。`areaCode` 与 `value` 同为 `a_uid`，兼容旧字段名。权限 `esp:expert:view` 或 `esp:draw:view`。

```json
{ "code": 200, "data": [
  { "key": "某某片区", "value": "PQ001", "areaName": "某某片区", "areaCode": "PQ001" }, "…" ] }
```

## 2. 三师信息管理接口（`/a/esp/expert`）

### 2.1 分页查询 `GET /a/esp/expert/page?name=张&org=设计院&selected=yes&pageNum=1&pageSize=10`

- `name`/`org` 模糊匹配，`selected=yes|no` 精确过滤（空 = 全部）；入库时间倒序；
- 返回 `data:{total, pageNum, pageSize, list:[专家行]}`。

### 2.2 统计卡 `GET /a/esp/expert/stat`

```json
{ "code": 200, "data": { "total": 24, "senior": 8, "selected": 6 } }
```

`total`=入库专家总数，`senior`=正高级工程师数，`selected`=已入选三师数。

### 2.3 专家详情 `GET /a/esp/expert/form?id=xxx`

查看/修改表单回显；`id` 为空返回 `{id:""}` 空骨架（新增表单默认值由前端合并）；不存在返回 400。

### 2.4 保存专家 `POST /a/esp/expert/save`（权限 `esp:expert:edit`）

`id` 空 = 新增，非空 = 修改；必填项与前端表单一致（name/gender/age/phone/idCard/field/title/org/orgType/selected/career/reviewExperience），服务端强校验（年龄 18~100；joinDate 可空）。

**登录账号**：保存时按**专家姓名**开通（姓名即登录名）：

1. 库内手机号不可与其他未删除专家重复；
2. 已有同名登录账号（`js_sys_user.login_code`=姓名）→ 仅绑定 `ESP_EXPERT.user_code`，不改其角色；若该账号尚无员工档案，则补齐以便在「用户管理」中可见；
3. 无账号 → 创建**员工用户**（`userType=employee` + `js_sys_employee`，与系统管理「用户管理」同一口径）、状态正常、初始密码=`ure.account.initPassword`（默认 `Ure@123456`）、授予 **urban_expert** 角色、**归属机构**固定为配置 `esp.expert.officeViewCode`（默认 `ZDTBZT001`，对应机构管理的「机构代码」）；找不到该机构则开通失败；归属公司可选；
4. 返回 `data:{id, name, accountCreated, loginCode}`（loginCode 为姓名）。评审提交时若三师尚未开通账号，会按姓名自动创建并绑定；已开通但用户管理看不到的历史 `expert` 类型账号，再次提交/保存专家时会补成员工档案。

已入库但尚未开通账号的专家，重新保存一次即可补绑。请将「评审管理」菜单授权给 `urban_expert` 角色，否则专家登录后看不到评审入口。在用户管理中请用**专家姓名**搜索登录账号。

```json
{ "id": "", "name": "张伟", "gender": "男", "age": 35,
  "phone": "13800000000", "idCard": "420102xxxxxxxx1234",
  "field": "城乡规划学", "title": "高级工程师",
  "org": "武汉市规划设计研究院", "orgType": "事业单位",
  "joinDate": "2026-09-08", "selected": false,
  "areaUids": ["PQ001"],
  "career": "……", "reviewExperience": "……" }
```

### 2.5 删除专家 `POST /a/esp/expert/delete?id=xxx`（权限 `esp:expert:edit`）

逻辑删除，并**级联逻辑删除**该专家全部评价记录；返回 `data:{id, name, deletedEvalCount}`。

### 2.6 导入模版地址 `GET /a/esp/expert/importTemplate`（权限 `esp:expert:view`）

返回 MinIO 上已上传的导入模版直链：

```json
{ "code": 200, "data": {
  "url": "http://host:9000/esp-files/esp/expert/templates/expert-import.xlsx",
  "fileName": "三师库批量导入模版.xlsx",
  "objectKey": "esp/expert/templates/expert-import.xlsx" } }
```

### 2.7 下载导入模版 `GET /a/esp/expert/importTemplateFile`（权限 `esp:expert:view`）

后端从 MinIO 读取模版字节，以附件流返回。

### 2.8 批量导入专家 `POST /a/esp/expert/importData`（权限 `esp:expert:edit`）

`multipart/form-data`，字段名 `file`（xlsx/xls）。表头须与系统模版一致；第 2 行含「范例」自动跳过。所属更新片区可空，多个用英文 `;` 分隔（按片区全称解析）。

```json
{ "code": 200, "msg": "导入完成：成功 3 条，失败 1 条",
  "data": { "success": 3, "fail": 1, "skip": 1,
    "errors": [{ "row": 4, "name": "李四", "msg": "联系电话须为 11 位手机号" }] } }
```

## 3. 随机分配三师接口（`/a/esp/draw`）

### 3.1 随机抽取 `POST /a/esp/draw/draw`（权限 `esp:draw:view`，不落库）

```json
{ "districtCode": "PQ001", "fields": ["城乡规划学", "建筑学"],
  "roles": ["planner", "assessor"], "avoidDrawn": true, "excludeIds": [] }
```

- `districtCode` 为 `ESP_MAP_AREA.a_uid`（片区下拉的 value）；
- 候选池 = 未删除专家 ∧（`fields` 空 = 不限领域，否则 field 命中）∧（`avoidDrawn` 默认 true：排除已入选三师）∧ 排除 `excludeIds`；
- 随机在服务端完成，按 规划师→建筑师→评估师 顺序各取一名，**同一批次不重复**；候选不足的角色为 `null`（前端提示无候选）；

```json
{ "code": 200, "msg": "抽取成功", "data": {
  "districtCode": "PQ001", "districtName": "某某片区", "poolSize": 12,
  "planner": { "专家行" }, "architect": null, "assessor": { "专家行" } } }
```

### 3.2 单角色随机更换 `POST /a/esp/draw/replace`（权限 `esp:draw:view`）

```json
{ "fields": ["城乡规划学"], "role": "planner", "avoidDrawn": true,
  "excludeIds": ["当前批次已抽中的专家id"] }
```

返回 `data:{role, expert:专家行}`；无合格候选返回 400「无符合条件的候选专家，无法更换」。

### 3.3 确认选用 `POST /a/esp/draw/confirm`（权限 `esp:draw:edit`）

```json
{ "districtCode": "PQ001", "fields": ["城乡规划学"],
  "plannerId": "xx", "architectId": null, "assessorId": "yy", "assignFlag": false }
```

- 至少一个角色专家非空；专家必须存在；**同一专家不能同时担任多个角色**（400）；
- 「指定人员」方式确认同样走本接口，`assignFlag=true` 标记；
- 落 `ESP_DRAW_RECORD`（片区/领域/角色专家快照 + 抽取人数 + 当天日期），并将入选专家置 `selected='1'`；
- **同一片区已有分配记录时覆盖最近一条**（不新增），返回 `overwrite=true`；
- 返回 `data:{recordId, drawCount, expertIds, overwrite}`。

### 3.4 分配记录分页 `GET /a/esp/draw/records?districtCode=PQ001&pageNum=1&pageSize=10`

抽取时间倒序；每行含三师姓名快照：

```json
{ "code": 200, "data": { "total": 8, "pageNum": 1, "pageSize": 10, "list": [
  { "id": "xx", "districtCode": "PQ001", "districtName": "某某片区",
    "drawFields": "城乡规划学、建筑学", "drawCount": 2,
    "plannerId": "p1", "plannerName": "张伟",
    "architectId": null, "architectName": null,
    "assessorId": "a1", "assessorName": "王芳",
    "drawDate": "2026-09-08", "assignFlag": false,
    "createByName": "管理员", "createDate": "2026-09-08 10:00:00" } ] } }
```

### 3.5 分配记录详情 `GET /a/esp/draw/record?id=xxx`

记录行（同上）+ 三个角色键 `planner/architect/assessor`（完整专家行或 null），供详情弹窗。

### 3.6 片区最近分配记录 `GET /a/esp/draw/latest?districtCode=PQ001`（权限 `esp:draw:view`）

选择片区后回显已抽取专家：按 `a_uid` 取该片区最近一次确认选用结果（含三角色完整专家行）；无记录 `data` 为 `null`。

## 4. 考评分析接口（`/a/esp/evaluation`）

### 4.1 三维度 Top5 排名 `GET /a/esp/evaluation/rank`

按历史评价平均分降序取前 5（平均分保留 1 位小数；无评价专家不参与）：

```json
{ "code": 200, "data": {
  "activity":   [ { "expertId": "xx", "name": "张伟", "org": "…", "avgScore": 9.2, "count": 3 }, "…至多5项" ],
  "coverage":   [ "…" ], "efficiency": [ "…" ] } }
```

### 4.2 已入选专家列表 `GET /a/esp/evaluation/list?name=张`

仅 `selected=1` 的专家（考评打分对象清单），姓名模糊过滤，整包返回；专家行 + 聚合字段：

```json
{ "code": 200, "data": [ { "专家行…", "avgActivity": 8.5, "avgCoverage": 9, "avgEfficiency": 7.5, "evalCount": 2 } ] }
```

### 4.3 历史评价分页 `GET /a/esp/evaluation/page?expertId=xxx&pageNum=1&pageSize=10`

按专家查询，评价时间倒序：

```json
{ "code": 200, "data": { "total": 3, "list": [
  { "id": "xx", "expertId": "yy",
    "activityStars": 4.5, "activityScore": 9,
    "coverageStars": 4, "coverageScore": 8,
    "efficiencyStars": 3.5, "efficiencyScore": 7,
    "time": "2026-09-08", "evaluator": "管理员", "org": "市住更局", "comment": "…" } ] } }
```

### 4.4 新增评价 `POST /a/esp/evaluation/save`（权限 `esp:evaluation:edit`）

```json
{ "expertId": "xx", "activityStars": 4.5, "coverageStars": 4,
  "efficiencyStars": 3.5, "time": "2026-09-08", "comment": "…" }
```

- 星数必填，0~5 且 0.5 整数倍（否则 400）；`time` 空默认当天；`comment` ≤1000 字；
- **评价人/评价单位取当前登录用户快照**（evaluator=用户姓名、org=部门名称），不接受前端指定；
- 返回 `data:{id, expertId, expertName}`；平均分随查询实时重算。

### 4.5 删除评价 `POST /a/esp/evaluation/delete?id=xxx`（权限 `esp:evaluation:edit`）

逻辑删除单条；返回 `data:{id, expertId}`。

## 5. 落库与审计说明（后端行为，前端无需处理）

- 全部删除为逻辑删除（`del_flag` 置 1）；删除专家级联删除其评价记录；
- 专家新增/修改/删除、评价新增/删除、分配确认均写 `ESP_OPERATE_LOG` 审计流水（操作人/部门快照 + 内容明细 JSON），日志失败不阻断业务；
- 主键为框架 IdGen 生成的 32 位串，前端无需生成 id；
- 建表脚本：`modules/esp/db/{postgresql,dm}/esp_expert_pool.sql`（5 表 + 26 行字典种子 + 5 条幂等菜单注册，需在目标库执行）。
