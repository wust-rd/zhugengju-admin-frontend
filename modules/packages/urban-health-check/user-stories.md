# 城市体检管理系统 · 用户故事

> 从 `modules/packages/urban-health-check` 现有代码反推整理(2026-09-02)。
> 当前系统为纯前端假数据阶段(后端未接入),故事中的行为均来自代码实现;标注「待接入」的为后端就绪后补齐的部分。

**角色**

| 角色 | 说明 |
|------|------|
| 市级填报员 | 市住更局,维护全市体检数据 |
| 市级管理员 | 管理指标体系框架与提交 |
| 区级填报员 | 区住更局,维护本区数据(带空间/规划属性) |
| 领导/查看者 | 浏览看板与各列表,只读 |

---

## Epic 1:运行健康看板(总览)

- **US-1.1** 作为领导/查看者,我希望进入城市体检模块先看到健康看板,以便一眼掌握全市体检的整体状况。
  - 验收:展示体检年份筛选、指标评价结果分布(很好/较好/一般/较差/无标准五档占比图)、分维度的重点指标卡片(生态宜居等折叠面板,含指标值与评级)。

## Epic 2:指标体系管理(市级/区级共用)

- **US-2.1** 作为填报员,我希望按体检年份、(区级另有)体检片区/行政区划/功能定位筛选指标体系列表,以便快速定位要维护的体系。
- **US-2.2** 作为填报员,我希望新增/编辑/查看/删除指标体系(年份、名称、指标数量、填报单位/时间、启用状态、提交状态),以便管理每年的体检体系台账。
- **US-2.3** 作为填报员,我希望点击体系名称进入该体系的指标项维护页(RESTful `/indicator-system/{code}`),以便在体系上下文里维护具体指标;页签标题显示体系名,侧边栏保持点亮上级菜单。
- **US-2.4** 作为填报员,我希望**只有待提交的体系才能编辑/删除**(已提交的锁定这两个操作),以便已提交的数据不被误改。
- **US-2.5** 作为区级填报员,列表/搜索/表单要额外体现 体检片区(街道)、行政区划(区)、功能定位(多选 TOD/COD/HOD/IOD/EOD,显示为拼接文本),以便区级数据带上空间与规划属性。

## Epic 3:指标项维护(体系 show 页)

- **US-3.1** 作为填报员,我希望在体系页顶部看到统计卡片——体系名、年份、填报进度(「已填报 X / 系统指标项 Y 项」进度条)、提交发布按钮,以便掌握填报完成度并触发提交。
- **US-3.2** 作为填报员,我希望指标按 一级/二级/三级维度 归属展示(一、二级同值合并单元格,跨页时组名重显,三级可空),以便按体检维度框架阅读长列表。
- **US-3.3** 作为填报员,我希望维护指标的 指标项名称/单位/指标来源/数据来源/责任部门,以便描述每项指标的定义与责任归属(来源取值如「武汉市特色指标」「区级统计」「市级调查-大数据」,责任部门「市住更局/各区政府」)。
- **US-3.4** 作为填报员,我希望通过抽屉表单新增/编辑/查看指标(查看模式整表禁用、无底钮),以便高频修改(「用户会修修补补」)且不误触。

## Epic 4:指标项结果管理

- **US-4.1** 作为填报员,我希望按年份/名称查看每个体系的**结果统计**——指标数量、已填报结果的指标数量、未填报数量、预警指标数量,以便跟踪填报进度和风险面。
- **US-4.2** 作为填报员,我希望点进某个体系的结果详情页(`/indicator-result/{code}`),用页签切换两类信息:**一级维度**(图层对象数量、图层覆盖面积 km²)与**指标项**,以便分别管理空间图层数据和指标结果。
- **US-4.3** 作为填报员,我希望在指标项结果表里维护每项指标的 **指标值、标准值/目标值**(数字)与 **评估结果**(较差/一般/较好/很好/无标准,彩色 Tag)、**预警状态**(红色预警/黄色预警/正常/无,彩色 Tag),以便形成体检结论(无标准的指标标准值留空、评估为「无标准」、预警为「无」)。
- **US-4.4** 作为填报员,详情页卡片同样展示已填报结果进度与提交发布,以便结果数据也有提交/版本动作。

## Epic 5:满意度调查

- **US-5.1** 作为填报员,我希望维护每年一次的满意度调查记录(调查年份、填报时间、数据来源、调查问题数量、有效调查问卷数、综合满意度%),以便留存年度民调台账(年份或数据来源列可点入明细)。
- **US-5.2** 作为填报员,我希望进入某年调查的问题明细页(`/satisfaction-survey/{code}`),维护每个调查问题(问题文字、面向对象)及**五档满意度占比**(非常满意/满意/一般/不满意/非常不满意,合计 100%),以便沉淀结构化的民调结果;卡片汇总显示综合满意度。

## Epic 6:体检成果管理(市级)

- **US-6.1** 作为填报员,我希望按年份管理市级体检成果目录(体检年份、成果目录、填报时间、提交状态),以便归档年度成果。
- **US-6.2** 作为填报员,我希望进入某个成果目录的分析明细页(`/achievement/{code}`),按一级维度维护**分析描述**与**程度范围**(一般/严重/特别严重,三色 Tag),以便形成问题诊断结论;卡片含提交发布。

## Epic 7:体检成果管理(区级,转置形态)

- **US-7.1** 作为区级填报员,我希望区级成果表把**五类成果清单展开为五列**(问题整治清单/发展机遇清单/更新诉求清单/基础资料库/更新项目储备建议库),行 = 某年某区片的记录(年份/片区/行政区划/功能定位/填报单位),以便按清单横向对比各区填报情况。
- **US-7.2** 作为区级填报员,我希望五列的内容是**各自的提交状态**(已提交/待提交),以便一眼看出哪个片区哪类清单还没交;点击体检片区(街道名)查看该行详情。

## Epic 8:通用与非功能

- **US-8.1(版本概念)** 作为填报员,体系/结果/成果都是**可提交的实体**:提交形成版本快照,之后仍可修改形成新版本(提交发布按钮 + 待提交/已提交状态驱动编辑锁定),以便支持「修修补补」的迭代式填报。
- **US-8.2(级别复用)** 作为开发者,市/区两级页面共用同一套抽象组件(shared 层),仅以「区级标记 + 路由基址」区分,以便新级别/新调整只改一处。
- **US-8.3(路由语义)** 所有下钻遵循 RESTful(`/资源/{code}` 隐藏菜单),id 恒为记录 code;页签以业务名命名;返回靠多页签栏。
- **US-8.4(数据来源体系)** 指标来源分国家/省/市级((住建部)国家指标等),数据来源分部门报送/统计年鉴/城市体检信息平台(区级另有 区级统计/市级调查-大数据),责任部门无则填 `/`——以便追溯每项数据的出处。
- **US-8.5(待接入)** 全部数据现为前端假数据(纯变量),后端就绪后替换为接口(列表/详情/保存/删除/提交),权限码(`v-auth`)与字典(年份/片区/区划/定位/状态)同步接入。

---

**一句话概括**:围绕「指标体系 → 指标项 → 结果填报 → 满意度/成果归档」的城市体检闭环,市级管全市纵向台账,区级带空间属性横向填报,以「提交 = 版本快照」控制数据成熟度。
