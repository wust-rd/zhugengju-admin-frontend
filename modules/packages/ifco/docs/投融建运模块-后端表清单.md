## 1. 分域表清单与标注

### 1.1 项目库（在库项目管理）—— `db/dm/ifco_lib_v4~v8.sql`

| 表名 | 标注（label 来自实体 @Table / 脚本注释） | 状态 |
| --- | --- | --- |
| ESP_MAP_PROJECT | **项目图斑 = 全系统项目主表**（esp 模块所有，跨模块共用）。唯一业务键 `p_uid`；库管理新建行 `fill_flag='2'`。三共享属性落在主表：`year_invest` 本年度计划完成投资、`start_date` 计划开工、`end_date` 计划完工；其余模块消费实施库项目直接读主表（`dist` 行政区、`wg_big` 五改分类、`inv_bil` 投资估算亿元、`area_name`/`batch` 片区与批次、`lib_project_code`、`pj_name`、`project_affiliation` 项目归属） | ✅ |
| ESP_PROJECT_EXTRA | **项目库管理扩展表**，`p_uid` 与主表 1:1。库生命周期与身份/审查文件；v6 加 `current_status` 当前状态、v7 加 `exit_type`/`exit_files`（转退出） | ✅ |
| IFCO_LIB_PROJECT_SUBJECT | **项目主体关联表**：行业主管部门 / 责任部门 / 指定填报主体 三类主体（ref 指向机构或公司） | ✅ |
| IFCO_LIB_REVIEW | **在库项目联合审查记录**（行业主管部门审核） | ✅ |
| IFCO_LIB_RESP_REVIEW | **在库项目责任部门审查记录**（conclusion pass/reject 驱动状态机） | ✅ |
| IFCO_LIB_TRANSFER_LOG | **在库项目流转日志**：申请转库/再申请/转入下库/转退出逐轮留痕（轮次号） | ✅ |

> 指定填报主体候选下拉的口径 = `js_sys_office`（按行业主管部门角色过滤）∪ `js_sys_company` 全量（`reportOrgOptions`），现场新建公司写 `js_sys_company` 并同步开账号；项目上的主体关联落 IFCO_LIB_PROJECT_SUBJECT。原候选机构字典表 IFCO_LIB_REPORT_ORG（v4 建后未用）已废弃，v8 脚本删除、v4 建表语句同步移除。

流程要点（详见《功能盘点-在库项目管理.md》）：策划库 → 储备库 → 实施库 三段流转，任一环节可转退出；状态由所在库决定，服务端状态机强制。**实施库是下游各填报模块的主数据源**。

### 1.8 资金管理（finance）—— ❌ 后端未接入，无自有表

前端 `api/ifco/finance/index.ts` 现状（文件头注释明示「资金后端未接入，刷新即恢复」）：

- **资金分类管理**：行集 = 实施库项目（/ifco/lib/project/page 翻页拉全量）∪ 最新年度任务已采纳项目（/ifco/annual/task + /plan/rows），会话缓存；**填报保存走会话内存 Map（fundFillStore）**——填报表单字段（纳统金额/资金缺口/REITs 培育/逐月到位资金 r104~r120 指标树）刷新即丢。
- **项目资金管理**：区划/片区/项目三形态汇总，逐月完成投资读 IFCO_MONTHLY_REPORT、逐月到位读内存填报值；片区元数据（编号/批次/功能定位/总体投资估算）读 **/esp/schemeFill/page**（策划方案，落 ESP_MAP_AREA）。
- **资金统计分析**：到位资金七分类饼图 + 资金流向桑基图，均基于上述内存填报值聚合。

流程测试视角：**资金是全模块唯一无持久化的业务闭环**，涉及保存/提交/统计分析联动的用例全部阻断在刷新恢复上。若补后端，至少需要：资金填报表（项目 × 月份 × 指标值 + 表单字段 + 填报状态 待填报/待提交/已提交）。

## 4. 流程测试关注点

1. **接口权限串**（Controller @RequiresPermissions，需与角色/菜单对齐）：
   `ifco:lib:view/edit`、`ifco:annual:view/edit`、`ifco:progress:view/edit`、`ifco:effect:view/edit`、`ifco:monthly:view/edit`、`ifco:schedule:view/edit`、`ifco:tricolor:view/edit`、`ifco:supervise:view/edit`、`ifco:projectfile:view/edit`、`ifco:impleffect:view`（impl-eval 的 save 未加权限注解——历史注释「菜单未配权限串，先登录即可访问」）。
2. **主数据链路顺序**（上游无数据则下游空转）：
   机构/公司初始化 → 项目库流转至实施库（ESP_MAP_PROJECT fill_flag='2'）→ 年度任务下达并提交（IFCO_ANNUAL_TASK.submit_status）→ 工作台采纳（ADOPT，含计划起止日期）→ 进度/成效/月报/倒排/三色填报（各自 PERIOD 开期）→ 督办闭环（dispatch→districtSubmit→urbanConfirm）→ 档案归集。
