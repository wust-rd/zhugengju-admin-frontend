# 在库项目管理（项目库管理）——功能、字段、权限、流转

> 页面路由：`/ifco/project-library-management/project-management/list`（菜单名称「在库项目管理」）
> 文档基准：2026-09-21 当前代码（dev 分支 + 未提交 WIP）
> 实现现状：**纯前端演示实现，后端零介入**（无 Controller/Service/DAO/数据库表/接口），数据为 api 层内存假数据（50 条，刷新即恢复）；所有流转操作为内存态。

## 1. 模块定位与代码位置

- **业务定位**：城市更新项目全生命周期台账。项目经历 **策划库 → 储备库 → 实施库** 三段生命周期，任一环节可退出，退出项目归集为 **已退出**（终态只读）。**项目状态由项目当前所在卡片库决定**。
- **代码位置**（均在 `zhugengju-admin-frontend`）：

| 文件 | 职责 |
| --- | --- |
| `modules/packages/ifco/api/ifco/project-library/index.ts` | 数据层：字段契约 `ProjectLibraryItem`、枚举字典、假数据仓库 `PROJECTS`、本地过滤 `filterProjects`、流转内存操作（applyTransfer / transferToNextLibrary / transferToExited）、指定填报主体清单 `REPORT_ORG_LIST` + `addReportOrg` |
| `.../project-library-management/project-management/list.vue` | 列表页：四库统计卡 + 视角切换 + 搜索表单 + 表格 + 工具栏 |
| `.../project-library-management/project-management/form.vue` | 查看/新增/编辑/审核一体表单抽屉（四步流转） |
| `.../project-library-management/project-management/review-block.tsx` | 审查结果区块（步骤②③共用，props 泛化） |
| `.../project-library-management/project-management/org-config-drawer.vue` | 配置指定填报主体抽屉 |
| `packages/ui/src/stepper.vue` + `types.ts` | Stepper 步骤条（支持 disabled 步骤禁用，本模块使用） |

- **与其他模块的关系**：impl-progress / impl-effect / finance 等模块仅复用本模块的行政区/片区/五改等**枚举口径**，项目行均为各自假数据；`ifco/impl-effect/project-management` 只是目录同名（属「实施成效评估」模块）；esp 图斑与 overview 大屏图层是独立数据。三字段转入全模块的业务口径见 §8。

## 2. 业务流程与流转

### 2.1 生命周期总览

```
区住更局统一录入 ──→ 策划库（待提交）
                        │  表单抽屉「申请转库」（校验+二次确认）→ 审核中
                        ▼
              行业主管部门 + 责任部门审核
                        │  审核通过 → 填报主体「转入下个库」；不通过 → 退回修改 → 再申请
                        ▼
                     储备库（转入后状态重置为待提交，同四状态流转）
                        │  再次申请转库 + 审核 + 转入
                        ▼
                     实施库（已入库）
                        │
                                                        ▼
                              ④ 已实施入库（流程状态页，无实际内容）

（任一状态：责任部门可「转退出」→ 已退出库，终态只读）
```

### 2.2 状态机（状态随所在卡片库决定）

| 状态 | 所在库 | 进入方式 | 语义 |
| --- | --- | --- | --- |
| 待提交 | 策划库/储备库 | 新录入；转入下个库后重置 | 库内初始态，可编辑、可申请转库 |
| 审核中 | 策划库/储备库 | 申请转库 | 等待行业主管部门与责任部门审核 |
| 退回修改 | 策划库/储备库 | 审核不通过 | 填报主体修改后可再次申请 |
| 审核通过 | 策划库/储备库 | 审核通过 | 填报主体可「转入下个库」 |
| 已入库 | 实施库 | 储备库转入 | 实施库在库状态（唯一状态） |
| 已退出 | 已退出 | 责任部门转退出 | 终态只读 |

状态 Tag 配色（列表状态列与表单标题 Tag 同源，`statusTagProps`）：审核通过=绿实心、已入库=蓝实心、已退出=灰实心、退回修改=橙描边、待提交/审核中=蓝描边。

### 2.3 状态流转动作

| 动作 | 触发位置 | 可操作视角/前置 | 状态变化 | 实现方式 |
| --- | --- | --- | --- | --- |
| 申请转库 | 表单抽屉页脚按钮（校验+Modal.confirm 二次确认） | 填报主体（暂存入口同） | 待提交/退回修改 → 审核中 | 内存：已有记录置审核中；**新增记录以策划库/审核中塞进 `PROJECTS`** |
| 审核 | 操作列按钮（审核中状态） | 行业主管部门、责任部门 | ——（推进到审核通过/退回修改**未实现**） | 以可写抽屉打开，审查人员在步骤②③填审查结论；缺审核结论落点（见 §7） |
| 转入下个库 | 操作列按钮（审核通过状态，二次确认） | 填报主体 | 策划→储备：状态重置**待提交**；储备→实施：直接**已入库** | 内存挪库 `transferToNextLibrary` + 列表重铺 |
| 转退出 | 操作列按钮（各状态，二次确认） | 责任部门 | → 已退出；记 exitedFrom（退出环节）/exitDate（当天）/exitReason | 内存挪库 `transferToExited` + 列表重铺 |

### 2.4 操作权限矩阵（`ACTIONS_BY_STATUS_ROLE`，状态×视角定稿口径）

| 状态 | 填报主体 | 行业主管部门 | 责任部门 |
| --- | --- | --- | --- |
| 待提交 | 查看、编辑 | 查看 | 查看、编辑、转退出 |
| 审核中 | 查看 | 查看、审核 | 查看、审核、转退出 |
| 退回修改 | 查看、编辑 | 查看 | 查看、编辑、转退出 |
| 审核通过 | 查看、转入下个库 | 查看 | 查看、转退出 |
| 已入库 | 查看 | 查看 | 查看、转退出 |
| 已退出 | 查看 | 查看 | 查看 |

矩阵为状态×视角双层 Record 穷尽（漏配编译报错）。操作按钮落地：查看=只读抽屉；编辑/审核=可写抽屉（传原引用以便内存流转生效）；转入下个库/转退出=二次确认后内存挪库。

### 2.5 角色与视角

- 三视角（`ROLE_OPTIONS`）：**填报主体**（report-org，默认）/ **行业主管部门**（industry-dept）/ **责任部门**（responsibility-dept）。
- 列表页表格上方「当前视角」RadioGroup 切换（演示阶段页面切换、生产接机构角色后按登录身份显隐，同 impl-progress 三视角模式）；切换重铺表格刷新操作列。
- 责任部门在业务上=市住更局（审查块中的责任部门固定为市住更局）。

## 3. 功能点清单

### 3.1 列表页（list.vue）

**① 四库统计卡**（单选 select 语义）：策划库（1,800 项/3,000 亿）/储备库（900/1,500）/实施库（830/1,300）/已退出（70，无投资）。点选=切换表格过滤库（URL `?library=` 持久化，默认策划库）。卡片数字为写死静态值，与表格 50 条假数据不对应。

**② 视角切换条**：见 §2.5。

**③ 搜索表单（8 字段，全部本地过滤 `filterProjects`）**：项目名称（模糊）/行政区（16 区）/片区名称（市级 6+区级 5 合计 11 项）/片区批次（第一批/第二批）/五改类别/入库年份（近 3 年，按 inLibraryDate 年份前缀）/最新项目状态（六状态）/项目归属。行政区条件同步 URL `?district=`（提交/重置更新、进页面回填），其余不进 URL。

**④ 表格（16 数据列）**：项目编号、项目名称（固定左）、行政区、片区名称、片区功能定位（**中英文结合**显示，如「交通导向（TOD）」）、片区批次、五改类别、主要建设内容、项目投资估算（亿元）、资金来源、项目归属、行业主管部门、责任部门、实施主体、统筹主体、指定填报主体、最新项目状态（固定右）。显示口径：多选顿号拼接、空值 `/`。复选框开启但无消费方（为批量操作预留）。分页走框架默认（每页 20，可切 10/20/50/80/100）。

**⑤ 操作列**：按 §2.4 矩阵出按钮，宽 240。

**⑥ 工具栏（6 按钮）**：配置指定填报主体（可用，见 3.4）/新增（可用）/一键提交、下载模板、一键导入、一键导出（**占位**，提示「功能待接入」）。

### 3.2 表单抽屉 form.vue（查看/新增/编辑/审核一体）

- 抽屉宽 70%；标题 = `查看/新增/编辑 · 项目名` + 状态 Tag；**页脚（footer 插槽自控）**：查看态仅「关闭」；编辑/新增态 = **取消 / 暂存 / 申请转库**（申请转库带二次确认，见 §2.3）。
- **暂存** = 校验并收集**步骤①基本信息表单**的值 → 关抽屉 → 提示「暂存成功（本地演示，未持久化）」→ 列表重铺。步骤②③的数据保存在抽屉内独立 ref，**不参与校验也不随提交组装**（TODO：后端接入后调保存/申请接口）。
- **四步流转步骤条**（Stepper 兼页签，可点击切换内容区；打开固定落步骤①；切换方向性滑动；面板 v-show 常驻不销毁；**无完成勾**——仅当前选中步骤为强调色，其余正常显示数字）：
  - ① 策划库入库 = 基本信息表单（三分区 FormGroup，两列布局，labelWidth 150）
  - ② 策划转储备 = 审查文件表单（六分区，labelWidth 180）
  - ③ 储备转实施 = 实施三分区 + 审查结果（labelWidth 180）
  - ④ 已实施入库 = 流程状态页（居中灰字「当前页面只表达流程状态，无实际内容」）
- **步骤点亮按项目所处库开放到「进行中」的步骤**（`accessibleStages`，Stepper disabled 项）：策划库=①②（填报主体新增项目后填写策划库入库与策划转储备）；储备库=①②③（①②只读、③储备转实施）；实施库=①②③④（④已实施入库可点亮）；已退出按退出环节映射（从策划库退出的③、从储备库退出的④不可点）；**储备库起步骤①②强制只读**（表单禁用、上传与审查块只读），仅步骤③可编辑。
- **已退出项目**：步骤条整条置灰（tone=gray，无完成勾，步骤按退出环节开放查看）；步骤条上方灰底横条只读展示 退出环节/退出时间/退出原因。
- **片区联动**（步骤①）：项目归属=市级更新片区内 → 片区名称下拉取前期规划已入库片区（6 个），选中带出片区批次/片区功能定位（**带出后不可改**），片区名称必填；区级 → 区级片区清单（不带出）；片区外零星 → 片区三件套整体隐藏。切换归属清空片区三件套。
- **指定填报主体联动**：选项=已选实施主体；实施主体清空时自动清空本字段；有实施主体时必选。
- **上传控件**：多文件不限量，`before-upload` 拦截仅记录文件名（假数据阶段），查看/只读态显示只读清单。
- **地理数据**：GeoDataSection（上传 shp/dwg「解析」渲染 + geoman 地图编辑，仅多边形工具）；解析为假实现（延迟 800ms 返回固定示例 GeoJSON）。

### 3.3 ReviewBlock 审查结果区块（步骤②③末尾通用）

- 顶部「**填报人再次发起 --- 时间**」记录行：业务口径=**表单被重新提交（再次发起）时记录一条**（跟 OA 一致的轮次概念）；现状为硬编码静态演示文案（无记录数据模型）。
- 轮次标题「第一次审查」，其下两个审查主体（标题+切换按钮同行，浅灰圆角容器）：
  - **行业主管部门**：RadioGroup 按钮组多机构切换（固定 3 家=行业主管部门清单去掉市住更局，**不随项目已选行业主管部门联动**）。每家独立记录：审查要点核对（清单逐项三选一：符合/不符合/不涉及）+ 审查意见（200 字）+ 审查附件。机构切换内容滑动。
  - **责任部门（市住更局）**：核对清单每项**仅 符合/不符合** + 审查结论（通过审查/退回修改）+ 审查意见 + 审查附件。
- 核对清单与所属步骤的 FormGroup 分区一一对应（props `sections` 泛化）：步骤②=五材料区块（`REVIEW_SECTIONS`）、步骤③=实施三分区（`IMPL_REVIEW_SECTIONS`）。
- 数据独立两套：步骤② `jointReviewMap`/`responsibilityReview`；步骤③ `implJointReviewMap`/`implResponsibilityReview`。
- 只读态：内容只读、机构仍可切换查看。

### 3.4 配置指定填报主体抽屉（org-config-drawer.vue）

维护指定填报主体候选机构清单（api 层模块级内存状态 `REPORT_ORG_LIST`，初始 3 家，刷新恢复）：输入机构名称新增（按钮/回车同效），无限追加；**空名或清单内重名在输入框下方红字拦截**（`addReportOrg`，不走 message）；下方按序号平铺展示已配置机构。**暂无消费方**：表单「指定填报主体」选项仍取自已选实施主体，未接此清单。

## 5. 编辑权限体系（三层叠加）

| 层 | 控制 | 规则 |
| --- | --- | --- |
| ① 操作入口层 | 谁能对项目做什么 | §2.4 矩阵：状态×视角 → 可见操作按钮（查看/编辑/审核/转入下个库/转退出） |
| ② 步骤点亮层 | 抽屉里能进哪个步骤 | `accessibleStages`：按库开放到「进行中」步骤——策划库=①②；储备库=①②③；实施库=①②③④（④=流程状态页）；已退出按退出环节映射 |
| ③ 表单字段层 | 步骤内哪些字段可改 | 见下 |

表单字段层三种状态（步骤①②）：
- **formDisabled（整体只读，业务定稿）**：查看态 **或** 项目已转出策划库（`library !== 'planning'` 的非新增记录）→ 步骤①②整表单禁用（含上传变只读清单、地理数据区块、第一次审查 ReviewBlock）。**储备库起前两步骤只读，仅步骤③可编辑**。
- **identityLocked（字段锁定）**：判定同上（转出策划库）→ 13 个身份字段 dynamicDisabled（项目名称/项目代码/行政区/项目归属/片区名称/五改类别/五改细分类别/六带类型/行业主管部门/责任部门/统筹主体/实施主体/指定填报主体）。策划库内编辑态生效；储备库起被整体只读覆盖。
- **恒只读**：项目编号、入库时间、总体投资估算（自动生成）；片区功能定位、片区批次（带出字段）。

步骤③（储备转实施表单）：仅查看态禁用，储备库起可编辑（这正是步骤③的设计用途）。

## 6. 操作流程（用户视角）

1. **进入页面**：默认选中策划库卡，表格按策划库过滤；视角默认填报主体。
2. **切库/切视角**：点统计卡（URL `?library=` 变化）；切「当前视角」重铺操作列。
3. **查询**：8 字段搜索表单本地过滤；重置清空（行政区同步从 URL 移除）。
4. **查看**（全视角全状态）：抽屉只读（表单禁用、文件只读清单、审查块只读、页脚仅关闭），可点亮范围内切换四步页签浏览。
5. **新增**：工具栏「新增」→ 空表单（视为策划库）→ 填步骤① → **暂存**（校验通过即关抽屉提示）或 **申请转库**（校验+二次确认后以策划库/审核中落进内存仓库）。
6. **编辑**（填报主体/责任部门在待提交、退回修改）：策划库项目全表单可改；储备库项目步骤①②只读、点步骤③页签编辑。
7. **审核**（行业主管部门/责任部门在审核中）：可写抽屉打开，在步骤②③的审查结果块填结论/意见/附件。
8. **流转**：申请转库→审核中；审核通过后（状态推进待实现，见 §7）填报主体「转入下个库」；责任部门「转退出」→已退出库。
9. **占位**：一键提交/下载模板/一键导入/一键导出 → 提示「功能待接入」。

## 7. 待接入清单与已知占位

**后端整链路（全部未做）**：无数据源接口（假数据 `PROJECTS`）、无四库/状态流转接口、无保存/申请转库接口、无审核结论接口、无导入导出接口、无真实文件上传（一律 `before-upload` 拦截仅记文件名）、无 shp/dwg 解析接口（假解析）、无数据库表、无指定填报主体配置接口、无三字段向其余模块的共享/转入通道（见 §8）。

**前端已挂占位/未闭环**

- 暂存/申请转库不持久化、不组装步骤②③数据（只校验收集步骤①表单，TODO 注释在）；申请转库/转入下个库/转退出均为内存态（刷新恢复）。
