## 1. 模块定位与代码位置

- **业务定位**：城市更新项目全生命周期台账。项目经历 **策划库 → 储备库 → 实施库** 三段生命周期，任一环节可退出，退出项目归集为 **已退出**（终态只读）。**项目状态由项目当前所在卡片库决定**。
- **数据模型核心**（接口文档 v5）：全系统项目主表 **ESP_MAP_PROJECT**（唯一业务键 p_uid，库管理新建行 fill_flag='2'）+ 扩展表 **ESP_PROJECT_EXTRA**（p_uid 1:1，库生命周期+身份/审查文件）+ 联合审查 IFCO_LIB_REVIEW + 责任审查 IFCO_LIB_RESP_REVIEW + 流转日志 IFCO_LIB_TRANSFER_LOG + 候选机构 IFCO_LIB_REPORT_ORG。三字段共享属性（本年度计划完成投资/计划开工/完工）在**主表 year_invest/start_date/end_date**，其余模块消费实施库项目直接读主表三列。

## 2. 业务流程与流转

### 2.1 生命周期总览

```
区住更局统一录入 ──→ 策划库（draft 待提交）
                        │  表单抽屉「申请转库」（校验+二次确认→save+apply，轮次+1）→ reviewing 审核中
                        ▼
              行业主管部门 + 责任部门审核（review 模式「保存审查」）
                        │  责任部门结论 pass→审核通过 / reject→退回修改（再申请=RESUBMIT 轮次+1）
                        ▼
                     passed（审核通过）→ 填报主体「转入下个库」
                        │  planning→reserve：状态重置 draft（步骤③可编辑）
                        │  reserve→implementing：status=stored（已入库）
                        ▼
                     ④ 已实施入库（流程状态页，无实际内容）

（任一非退出态：责任部门可「转退出」→ exited 已退出，终态一切写操作 400）
```

### 2.2 状态机（状态随所在卡片库决定，后端英文枚举）

| 状态 | 中文 | 所在库 | 进入方式 |
| --- | --- | --- | --- |
| draft | 待提交 | 策划库/储备库 | 新录入；转入下个库后重置 |
| reviewing | 审核中 | 策划库/储备库 | 申请转库（apply，轮次+1） |
| rejected | 退回修改 | 策划库/储备库 | 责任部门结论 reject |
| passed | 审核通过 | 策划库/储备库 | 责任部门结论 pass |
| stored | 已入库 | 实施库 | 储备库转入（transferNext） |
| exited | 已退出 | 已退出 | 责任部门转退出（记 exited_from/exit_date/exit_reason） |

状态 Tag 配色：passed=绿实心、stored=蓝实心、exited=灰实心、rejected=橙描边、draft/reviewing=蓝描边。

### 2.3 流转动作（前后端闭环）

| 动作 | 触发位置 | 视角/前置 | 链路 |
| --- | --- | --- | --- |
| 申请转库 | 表单页脚（校验+二次确认） | edit 模式 | 前端 save（保最新）+ apply（轮次+1→reviewing；rejected 再申请记 RESUBMIT） |
| 审核 | 操作列（reviewing） | 行业主管部门/责任部门 | review 模式打开抽屉填审查块 →「保存审查」= reviewSave stage2+stage3；**结论落点**：conclusion 只随当前库对应 stage 提交（策划库=stage2、储备库=stage3），pass/reject 推进状态 |
| 转入下个库 | 操作列（passed） | 填报主体 | 二次确认 → transferNext（服务端校验 passed） |
| 转退出 | 操作列（各状态） | 责任部门 | 二次确认 → transferExit（原因前端暂传固定文案「责任部门转退出」） |
| 暂存 | 表单页脚 | edit 模式 | save **按组提交**：新建/策划库三组齐交（base/reviewFiles/impl）；储备库只提交 impl 组（base/reviewFiles 传 null，后端按组校验可编辑库）；impl 组同步写主表三字段 |

### 2.4 操作权限矩阵（状态×视角，前端控制）

| 状态 | 填报主体 | 行业主管部门 | 责任部门 |
| --- | --- | --- | --- |
| draft | 查看、编辑 | 查看 | 查看、编辑、转退出 |
| reviewing | 查看 | 查看、审核 | 查看、审核、转退出 |
| rejected | 查看、编辑 | 查看 | 查看、编辑、转退出 |
| passed | 查看、转入下个库 | 查看 | 查看、转退出 |
| stored | 查看 | 查看 | 查看、转退出 |
| exited | 查看 | 查看 | 查看 |

后端权限仅分 `ifco:lib:view`/`ifco:lib:edit`（菜单已配）；视角矩阵为前端控制，生产接机构角色。编辑的服务端硬校验：非策划库 save 返回 400（步骤③内容经 save 的 impl 组在储备库场景会被拦——**见 §7 已知问题**）。

## 3. 功能点清单

### 3.1 列表页
- **四库统计卡**：静态文案 + stats 接口数字（各库项目数/投资合计亿元，已退出卡无投资）；点选切库（URL `?library=`，默认策划库）。
- **视角切换条**：填报主体/行业主管部门/责任部门（默认填报主体），切换 reload 刷新操作列。
- **搜索表单 8 字段**（直传后端）：projectName（模糊）/district/areaName（市级 6+区级 5 合计）/batch/wgBig/year/status/affiliation；district 同步 URL `?district=`（beforeFetch 合入请求）。
- **表格**：useTable api 模式分页（pageNo→pageNum 适配、{total,list}→{list,totalCount} 适配）；16 数据列=后端联查列名小写（lib_project_code/pj_name/dist/area_name/func_type_name/batch/wg_big/content/inv_bil/fund_src/project_affiliation/industry_dept_list/resp_dept/implement_org_list/coordinate_org_list/report_org/status）；多选逗号串顿号展示、空值 `/`、状态英文经 STATUS_LABEL 中文 Tag；复选框无消费方；分页框架默认 20。
- **工具栏**：配置指定填报主体（可用）/新增（可用）/一键提交、下载模板、一键导入、一键导出（占位）。

### 3.2 表单抽屉（view/edit/review 三模式）
- 打开时 detail 接口回填（联查列 + reviews 两 stage + transferLogs + currentRound）；新增=空表单。
- **四步步骤条**：点亮按库（策划=①②、储备=①②③、实施=①②③④、已退出按 exited_from 映射）；无完成勾（仅当前选中强调色）；④=流程状态页（「当前页面只表达流程状态，无实际内容」）；储备库起步骤①②整体只读。
- **页脚**：view=关闭；edit=取消/暂存/申请转库（均先过步骤①校验）；review=取消/保存审查。
- ReviewBlock：机构切换+责任部门；conclusion select=通过审查(pass)/退回修改(reject)；顶部「填报人再次发起 --- 日期 操作人」=transferLogs 的 RESUBMIT 行（无记录不显示）。
- 总体投资估算：后端无此字段，恒空只读（自动计算待做）。
- 片区联动/指定填报主体联动/必填规则与假数据版一致。

### 3.3 值口径（前后端契约）
- 英文枚举：library（planning/reserve/implementing/exited）、status（draft/reviewing/rejected/passed/stored/exited）、conclusion（pass/reject）。
- 中文值：五改类别（wg_big）、五改细分（wg_sub）、片区批次（batch）、功能定位（func_type_name，顿号分隔）。
- **projectAffiliation=market/district/scattered**（后端定稿；前端 label=市级更新片区内/区级更新片区内/片区外零星）——**market 语义待用户确认**（见 §7）。
- 多选=逗号分隔串（六带/资金来源/行业主管部门/统筹/实施主体）；文件=JSON 数组串 `[{name,url,objectKey,size}]`（前端暂只写 name）。

## 5. 编辑权限体系（三层叠加，同前版）

1. **操作入口层**：§2.4 矩阵（前端视角×状态）。
2. **步骤点亮层**：按库开放（策划=①②；储备=①②③；实施=①②③④；已退出按退出环节）。
3. **表单字段层**：formDisabled（非 edit 模式或转出策划库→步骤①②整体只读，review 模式审查块放开）；identityLocked 13 字段（策划库内生效）；恒只读（项目编号/入库时间/总体投资估算/带出两字段）。步骤③申报字段仅 edit 模式放开。

## 6. 操作流程（用户视角）

1. 进入页面：默认策划库+填报主体视角，stats/page 接口加载。
2. 切库/切视角/搜索：reload。
3. 查看：只读抽屉（detail 回填）。
4. 新增：空表单 → 暂存（save，返回 p_uid/项目编号）或申请转库（save+apply→reviewing）。
5. 编辑：策划库全表单；储备库步骤①②只读、步骤③编辑 → 暂存。
6. 审核：review 模式填审查块 → 保存审查（结论推进状态）。
7. 流转：转入下个库/转退出（二次确认→接口→刷新列表与统计卡）。
8. 占位：一键提交/下载模板/一键导入/一键导出。
